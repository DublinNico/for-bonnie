# Bonnie — website

The Next.js site for the Bonnie photomosaic. Live at **https://for-bonnie.vercel.app**.
For the project as a whole (and how the mosaic is made), see the [main README](../README.md).

## Run it

```bash
npm install
npm run dev          # http://localhost:3000 — reloads as you edit
```

| Command | What it does |
|---------|--------------|
| `npm run dev` | development server |
| `npm run build` | production build — the same thing Vercel runs |
| `npm run start` | serve the production build (`-p 3001 -H 0.0.0.0` to open it from a phone on the same Wi-Fi) |
| `npm run lint` | ESLint |
| `npx next typegen && npx tsc --noEmit` | TypeScript check (as CI runs it) |

Needs Node.js 20.9 or newer (CI and Vercel use 24).

## How it's put together

The whole page is static: Next.js renders it to plain HTML at build time, and
only the interactive parts (explorer, gallery, photo view) run JavaScript in
the browser.

```
app/
  page.tsx                 the page: loads the mosaic data, lays out the sections
  layout.tsx               fonts (Instrument Serif + Hanken Grotesk), title, description
  globals.css              all styles — colour tokens at the top, mobile first,
                           desktop from 900px wide
  favicon.ico, icon.png, apple-icon.png   made by ../make_favicon.py
  lib/
    load-mosaic.ts         reads public/mosaic.json + the tile list (build time only)
    types.ts               Photo / MosaicData types, image URL helpers
  components/
    Hero.tsx               portrait between "Bon | nie"
    MosaicExperience.tsx   shared state: which photo is open / highlighted
    MosaicExplorer.tsx     the <canvas> mosaic: pan, zoom, tap to identify
    HowItWasMade.tsx       portrait -> colour grid -> mosaic
    Gallery.tsx            all photos, sortable
    Lightbox.tsx           full-size photo view, "Show in mosaic"
    Closing.tsx            dedication + polaroids
```

`Hero`, `HowItWasMade` and `Closing` are server components (no JavaScript
sent to the browser). The explorer, gallery and lightbox are client
components (`"use client"`), wrapped by `MosaicExperience` because they share
state.

## Where the data comes from

Everything in `public/` is generated by the Python scripts in the project root:

| File | Made by |
|------|---------|
| `public/mosaic.json` — grid size + which photo is in each cell | `bonnie.py` |
| `public/tiles/{xs,sm,lg}/` — every photo at 96 / 400 / 1000 px | `make_web_assets.py` |
| `public/mosaic-preview.webp`, `portrait.webp`, `grid.png` | `make_web_assets.py` |

If a photo named in `mosaic.json` has no web image, the build stops with a
message telling you to run `make_web_assets.py`.

## Deploying

Vercel project `nicoletti-dev/for-bonnie`, connected to GitHub with root
directory `site`. Every pull request gets a preview deployment; merging into
`main` deploys the live site. CI (`../.github/workflows/ci.yml`) runs lint,
type-check and build on every PR.

## Gotchas

- **This is Next.js 16**, which changed some APIs. Check the docs bundled in
  `node_modules/next/dist/docs/` before relying on older examples (see
  `AGENTS.md`).
- **`LayoutProps` is a generated type.** It only exists after `next dev`,
  `next build` or `next typegen` has run — which is why CI runs
  `next typegen` before `tsc`.
- **Windows on ARM:** if `npm run dev` fails with
  `Cannot find module '…win32-arm64…'`, the packages were installed for x64.
  Delete `node_modules` and `package-lock.json` and run `npm install` again.
- `.vercel/` and `.env.local` are created by the Vercel CLI and are
  git-ignored. `.env.local` contains a token — don't commit or share it.
